# 子弹视觉修饰符叠加系统 · 设计规格

> **版本**：v1.1
> **日期**：2026-08-03（v1.0 定稿 → v1.1 修订）
> **目标平台**：NeoForge 1.21.1
> **状态**：已审查，修订后待实施
> **相关模块**：`bullet/`、`registry/gun/`、`network/`、`client/render/`
> **取代**：现有 `BulletStyle`（整体覆盖语义）、`VisualStyleResolver`（废弃删除）

## 1. 背景与动机

### 1.1 现状问题

当前 `BulletStyle` 采用"整体覆盖"语义：插件的 `bullet_style` 完整替换枪械的 `bullet_style`（包括 model、render_mode 全部字段），高优先级插件 last-wins。这与《以撒的结合》的子弹变化理念相反——以撒里每个道具独立贡献一个对眼泪/子弹的变换（变大、染红、加拖尾），多个道具的效果**同时叠加**生效，组合出复杂外观。

实际代码核查发现两处缺陷：

1. **`VisualStyleResolver`（`bullet/VisualStyleResolver.java`）从未被引用**——它本应实现插件整体覆盖链，但全项目无调用。
2. **实际生效的 `BulletSyncService.resolveVisualStyle` 只查枪械定义的 `bulletStyle()`**，完全忽略插件覆盖链。即当前任何插件声明的 `bullet_style` 覆盖都不会在子弹外观上生效。

### 1.2 重设计目标

以"修饰符叠加组合"取代"整体覆盖"，使不同来源的视觉变换能像以撒道具那样**结合到一起**：预置一个最基础的子弹模型，插件/枪械/特性/状态以修饰符的方式修改其大小、叠加颜色、叠加附加模型层。

## 2. 核心设计基线

经过 10 轮澄清，确立以下基线：

| # | 维度 | 结论 |
|---|------|------|
| 1 | 修饰符来源 | 枪械 + 插件（静态声明）+ 特性 + per-gun/per-bullet 状态（动态） |
| 2 | 渲染形态 | 基础+附加层双轨制：变换型合并入基础，附加型作独立层并行绘制 |
| 3 | 基础子弹 | 枪械定义声明基础外观，未声明用框架内置 fallback |
| 4 | 大小边界 | `bullet_size` 属性管碰撞；视觉 `renderScale` 修饰符独立 × 管渲染 |
| 5 | 颜色组合 | 逐通道乘法 tint（RGB×，白色 (1,1,1,1) 为恒等） |
| 6 | 附加层朝向 | 每层自带参数：`follow_rotation` / `follow_scale` / `offset` |
| 7 | 运行模型 | 声明式为主（含 trait 激活、state 条件阈值）；复杂动态用 `onVisualTick` 代码钩子 |
| 8 | 冲突解决 | 自动规则：乘子类连乘叠加；绝对设置类按优先级 last-wins，同优先级按安装顺序 |
| 9 | 修饰符载体 | 内联声明，无新注册表（B 方案） |
| 10 | 组合位置 | 服务端组合初值，`FullBulletEntry` 携带组合结果（X 解法） |

### 2.1 核心原则修正

原头脑风暴第一节提出"服务端不下场合成视觉、客户端本地推导"。核查 `ClientBulletSnapshot` 后发现该原则在插件/状态两类来源上**不可行**——客户端缺 `installedPlugins` 列表（`GunData.installedPlugins` 不进 `ClientBulletSnapshot`），且 state 初值当前**无任何传输通道**（`BulletSnapshot.encodeState/decodeState` 已写但从未接入任何网络包，`BulletSyncService.toClientBulletSnapshot` javadoc 明说"state map omitted"，该路径目前是断的）。补齐这两项均需新建传输，开销大于服务端组合后只发结果的开销。

**立得住的原则**是：**仅用初值组合一次，飞行中 state 变化不重发，`onVisualTick` 代码钩子兜底动态**（路径①）。组合发生在服务端只是实现手段，不削弱任何客户端动态能力——`onVisualTick` 钩子在客户端读 `ClientBulletSnapshot`（已同步 traits/stats）改 `BulletRenderObject` 的能力完全保留。

> **创建瞬间冻结（v1.1 明记）**：`compose()` 仅在子弹创建瞬间的同步 tick 运行一次，结果缓存到 `BulletRecord`；之后所有 `toFullBulletEntry` 调用点（创建当 tick 的 `collectCreatedThisTick:411`、新进渲染距离的 `collectActiveBulletDeltas:450`、forceFullSync 重连/跨维度的 `collectActiveFullEntries:333`）**全部复用缓存**，不重跑组合。因此：
> - `BulletSnapshot.stats/traits/state/damageType` 虽 javadoc 标注为"故意可变、钩子可在飞行中改"，**视觉层不响应这种飞行中变更**——视觉组合是创建瞬间冻结的。
> - 若钩子要在飞行中改视觉，应走 `onVisualTick` 钩子改 `BulletRenderObject`（客户端层面），而非改 `BulletSnapshot` 以期重组合。
> - 此为相对当前代码的 **behavior change**：现状 `BulletSyncService.toFullBulletEntry` 每次 full-entry 都重跑 `resolveVisualStyle`，本设计改为创建时缓存、复用。

## 3. 数据结构

### 3.1 `bullet_style` 字段结构（枪械 / 插件 / 特性 / 状态 通用）

```jsonc
"bullet_style": {
  "base": {                          // 可选；基础外观，atomic，priority last-wins
    "render_mode": "billboard",      // "billboard" | "3d"
    "texture": "m:textures/bullet/default.png",   // billboard 模式用
    "model":   "m:models/bullet/default.json"     // 3d 模式用
  },
  "modifiers": [                     // 可选；修饰符数组，逐个按类型规则组合
    { "type": "scale", "value": 1.5 },
    { "type": "tint",  "color": [1.0, 0.3, 0.2] },
    { "type": "attach_layer",
      "render_mode": "billboard",
      "texture": "m:textures/bullet/flame.png",
      "follow_rotation": false,
      "follow_scale":    true,
      "offset":          [0.0, 0.1, -0.3],
      "scale":           0.8,
      "tint":            [1.0, 0.5, 0.2, 1.0] }
  ]
}
```

### 3.2 修饰符类型（仅三种，覆盖全部以撒式需求）

| `type` | 作用 | 合并规则 | 字段 |
|--------|------|---------|------|
| `scale` | 变换型 · 改基础大小 | × 连乘：`final = ∏(scale.value)`；与 `bullet_size` 属性无关，只乘渲染 | `value`：number uniform 或 `[x,y,z]` per-axis |
| `tint` | 变换型 · 改基础颜色 | × 逐通道连乘：`final = ∏(rgb)`；白色 (1,1,1,1) 为恒等 | `color`：`[r,g,b]` 或 `[r,g,b,a]`，alpha 默认 1.0 |
| `attach_layer` | 附加型 · 加独立层 | 全部生效（无冲突，并行绘制）；每层自带 scale×、tint× 对层内独立应用 | `render_mode` / `texture`\|`model` / `follow_rotation` / `follow_scale` / `offset[3]` / `scale` / `tint` |

### 3.3 合并语义

- **`scale` / `tint`**：所有来源的乘子修饰符逐一 × 连乘（顺序无关），不丢任何一个。这是以撒式叠加的核心。
- **`attach_layer`**：所有来源声明全部保留，按来源顺序入队并行绘制；每层有自己独立的 scale/tint 跟随参数，互不干扰。
- **`base`**（texture\|model + render_mode 三位一体）：唯一走 priority last-wins 的维度，因为 billboard 纹理与 3d 模型不能混搭，必须整组替换。枪械自己的 base 固定最低优先级（priority 0）；插件 base 按 `PluginDefinition.priority()`，同优先级按 `installedPlugins` 安装序后装赢。没有任何来源声明 base 时用框架 fallback。

### 3.4 Java 数据模型

```java
// registry/gun/BulletStyle.java（改造）
public record BulletStyle(
        Optional<Base> base,
        List<Modifier> modifiers
) {
    public record Base(RenderMode renderMode, @Nullable ResourceLocation texture, @Nullable ResourceLocation model) {}
    // Codec: dispatchMap by "type"
}

public sealed interface Modifier permits ScaleModifier, TintModifier, AttachLayerModifier {
    String type();
}

public record ScaleModifier(float value) implements Modifier { /* type="scale" */ }
public record TintModifier(Vector4f color) implements Modifier { /* type="tint"; (r,g,b,a) */ }
public record AttachLayerModifier(
        BulletStyle.RenderMode renderMode,
        @Nullable ResourceLocation texture,
        @Nullable ResourceLocation model,
        boolean followRotation, boolean followScale,
        Vec3 offset, float scale, Vector4f tint
) implements Modifier { /* type="attach_layer" */ }
```

> `Modifier` 为 sealed interface，Codec 用 `dispatchMap` 按 `type` 字段分发到对应 record 的子 Codec。
>
> **`org.joml.Vector4f` 注**：项目此前无 `Vector4f` 使用先例（仅 `BillboardRenderer` 用 `org.joml.Vector3f`）。NeoForge 21.1.233 经由 MC 1.21.1 透传 JOML 1.10.5，`Vector4f` 已在编译类路径，无需显式声明依赖。本设计**首次引入**该类型。
>
> **网络层取舍（主动决策，非沿用默认）**：备选 `int` packed color（`0xAABBGGRR`，4 bytes）比 `Vector4f`（16 bytes）每子弹省 12 bytes，`LayerEntry` 内 `tint` 同省。本设计**主动选 `Vector4f`**：
> 1. `compose()` 连乘累积与 `BillboardRenderer`/`Model3DRenderer` 顶点色相乘的入口都是 floattuple，选 `Vector4f` 免去 pack/unpack 常量转换；
> 2. 多数子弹 `composedTint == null`（白色恒等）走 null 标志字节传输，关键省网络路径已覆盖；
> 3. `Codec` 与调试可视化上 `Vector4f` 比 packed `int` 直观。
>
> 若未来 `attach_layer` 密集场景 byte 体积成瓶颈，可在 wire codec 层降为 packed `int` 而 `ComposedBulletStyle`/`BulletRenderObject` 仍持 `Vector4f`——本设计不堵这条路，但当前不引。

### 3.5 状态条件修饰符（声明式表达动态）

per-gun/per-bullet state 可声明"条件 → 启用修饰符"：

```jsonc
// stateDefinition 的新增字段（可选）
"visual_modifiers": [
  {
    "condition": { "state": "modularshoot:killstreak", "domain": "bullet", "op": ">=", "value": 3 },
    "modifiers": [
      { "type": "tint", "color": [1.0, 0.2, 0.2] },
      { "type": "scale", "value": 1.2 }
    ]
  }
]
```

条件所属 state 取值**仅以子弹创建瞬间的初值**判定（路径①约束）；子弹飞行中 state 跨过阈值不会自动视觉变更，上层模组需要时写 `onVisualTick` 钩子主动响应。即使子弹在飞行中被某钩子改了 state（`BulletSnapshot.setState`）或 traits（`setTrait`），组合结果**不会重算**——视觉组合只在创建瞬间跑一次并缓存到 `BulletRecord`（详见 §2.1 "创建瞬间冻结"注与 §4.1 `BulletRecord` 缓存行）。

条件操作符（op）：`>=` / `<=` / `==` / `>` / `<`（数值型 state，含 INT / LONG / DOUBLE / FLOAT），`==`（布尔型 state 与 STRING）。UUID 类型 state 不支持条件判定，命中时按 §5 skip + WARN 降级。

> **domain 解析**：state id 在不同 domain 可重名。condition 定义可选 `domain` 字段（取值与 `StateDefinition.domain` 的 `StateDomain` 枚举一致）。缺省时按固定规则解析：**先查 per-bullet `BulletSnapshot.state` map，未命中再查 per-gun `GunData.state` CompoundTag**；命中失败或类型不匹配按 §5 错误处理降级（skip + 走 `StateWarnLogger`）。

> **op 求值器为新增子系统**：项目现状无任何 condition evaluator 或操作符枚举可沿用（全仓 grep 零命中）。本设计需从零编写 op 枚举 + `boolean eval(stateValue, threshold)` 求值器；求值之外的降级日志可直接复用 `StateWarnLogger` 三函数（warnUnregistered / warnTypeMismatch / warnDomainMismatch）。

### 4.2 `VisualCompositionService.compose()` 算法

> **调用时机**：仅在子弹创建瞬间跑一次并缓存——详见 §4.1 "运行时机"注与 §2.1 "创建瞬间冻结"注。本算法对同一子弹**至多跑一次**。

```
compose(registryAccess, snapshot, gunData):
    1. 收集所有来源的 base 候选与 modifiers:
       a. gunDef.bullet_style.base/modifiers        (priority 0)
       b. for each pluginInstance in gunData.installedPlugins (按列表序保留安装序):
            通过 pluginInstance.pluginId() 反查 PluginRegistry 取 pluginDef
            pluginDef.bullet_style.base/modifiers    (priority = pluginDef.priority())
       c. for each traitId where snapshot.traits[traitId] == true:
            traitDef.visualModifiers                 (顶层 scale/tint/attach_layer 入组合;
                                                      trait 不参与 base last-wins)
       d. for each stateDef with visual_modifiers:
            按 condition.domain 解析 state 源:
              显式 domain → 直接查对应 StateRegistry + 对应源 map（per-bullet / per-gun）
              缺省 domain → 先查 per-bullet snapshot.state, 未命中查 per-gun gunData.state
            读 state 初值 → StateConditionEvaluator 求值, 条件成立者 modifiers 入组合
                                                     (priority = stateDef 自身)
    2. base 选取: 按 priority 降序, 同 priority 按 install 序后装赢, 取 winner.base;
       无 base 候选 → FALLBACK_BASE
    3. renderScale = ∏(各源 .modifiers 数组顶层 ScaleModifier.value, 每个 clamp finite >0);
       无 → 1.0
       ; attach_layer 内嵌的 scale 不参与连乘, 仅作用于该层
    4. composedTint = ∏(各源 .modifiers 数组顶层 TintModifier.color, 逐通道); 无 → (1,1,1,1)
       ; attach_layer 内嵌的 tint 不参与连乘, 仅作用于该层
    5. layers = 全部 attach_layer 收集, 按来源序入队; 各层内嵌 scale/tint 独立作用于本层
    6. return ComposedBulletStyle(base, renderScale, composedTint, layers)
```

### 4.4 `scale` 字段语义清理（重要）

现有 `FullBulletEntry.bulletSize: float` 语义不清——既是视觉缩放又映射碰撞。重设计下拆清：

- **`bullet_size`（碰撞）**：保留在 `BulletSnapshot.stats[bullet_size]`，走属性管线，服务端 `CollisionDetector` 用。**不再进视觉字段**。
- **`renderScale`（视觉缩放）**：`VisualCompositionService` 组合的 `∏(scale.value)` 写入新字段 `renderScale`。默认 1.0；无 scale modifier 时不乘。
- **字段名 `bulletSize → renderScale`**（同位同类型，仅变量名 + 语义变更）。内部协议无第三方依赖，同步改 codec 即可，无跨版本兼容负担。

> **`RenderMode` 枚举↔字符串跨层转换（沿用现状，不新增机制）**：本项目 `RenderMode` 在不同层有两种表达，本设计维持不变更：
> - **JSON/datapack 层**：枚举 `BulletStyle.RenderMode`（`BILLBOARD("billboard")` / `THREE_D("3d")`，`StringRepresentable`，`registry/gun/BulletStyle.java:40-55`），由 `RenderMode.CODEC` 解析。
> - **网络层**：`FullBulletEntry.renderMode: String` 与 `LayerEntry.renderMode: String` 均为字符串，wire 走 `buf.writeUtf/readUtf`（`BulletS2CPacket.java:210,233`）。`compose()` 输出 `Base.RenderMode` 枚举；填 `FullBulletEntry` 时调用方（`BulletManager.fireBullet` 缓存读出处，沿用 `BulletSyncService.java:648` 现有写法 `RenderMode.getSerializedName()`）转成 `"billboard"`/`"3d"`。
> - **客户端层**：`BulletRenderObject.RENDER_MODE_BILLBOARD`/`RENDER_MODE_3D` 两个常量本身也是 `RenderMode.X.getSerializedName()` 转的字符串常量（`BulletRenderObject.java:45,48`），`BulletRenderDispatcher.renderByMode` 直接 `String.equals` 比对（`BulletRenderDispatcher.java:178-188`）。
> 实施要点：`ComposedBulletStyle` 内部以枚举保存 `Base.renderMode`，网络编码处用 `getSerializedName()` 落到 String；客户端装填与若干层渲染均用现有 String 常量，**无需动枚举/字符串编译期链接**。`attach_layer` 的 `RenderMode` 走同样的 enum→String 一次转换入 `LayerEntry.renderMode`。

### 4.6 服务端 `BulletSnapshot` 不动

- `stats`（属性 → 碰撞用）、`traits`、`state` map 字段——不变
- 说明：`BulletSnapshot.encodeState/decodeState` 在项目现状中**无任何调用者**（`BulletSyncService.toClientBulletSnapshot` javadoc 明确"state map omitted"）。该断路本设计**不修复**——state 数据原样只在服务端停留
- 服务端组合时**临时读取** state map（per-bullet `BulletSnapshot.state` 与 per-gun `GunData.state`）做条件阈值判断，**不引入任何新的 state 序列化**

## 5. 错误处理与降级

整个 `VisualCompositionService.compose()` **永远返回非 null `ComposedBulletStyle`**，不抛异常。降级行为沿用现有风格（设计文档 §定义丢失降级 + `StateWarnLogger` + missing model fallback）：

| 故障点 | 处理 |
|--------|------|
| `modifiers` 内某条 `type` 不识别 | 该条 skip + WARN，其余继续组合 |
| `scale.value` 非有限值（NaN/Inf）或 ≤0 | 该条 skip + WARN（不乘进去；`×NaN` 会污染全局 scale） |
| `tint.color` 通道值超 [0,1] | clamp 到 [0,1]，无 WARN（容忍 `<1.0001` 浮点误差）；负数或 NaN skip + WARN |
| `attach_layer` 的 `texture`/`model` 资源缺失 | billboard 退化不绘制该层；3d 走现有 missing-model 不崩溃 |
| 组合结果 `renderScale` 下溢 ≤0 / NaN | clamp 到 1.0，记 WARN |
| 组合后 0 个 layer、null tint | 正常状态，非错误（多数子弹无附加层、无染色） |
| `installedPlugins` 含的 pluginId 未注册 | 该条 skip + WARN |
| 状态条件修饰符引用的 state id 未注册 / domain 错 / 类型不匹配 | skip + WARN（沿用 `StateWarnLogger` 三函数） |
| 全部来源都没声明任何样式 | 返回 `DEFAULT`（billboard + `modularshoot:textures/bullet/default.png` + scale 1.0 + 白 tint + 空 layers） |
| 找不到枪械定义 | `DEFAULT`（独立发射场景） |

## 6. 测试策略

沿用现有 JUnit 模式（`build.gradle` 已配好测试源集继承主依赖，参考 `StateDefinitionCodecTest`）。只测**纯函数层**——`VisualCompositionService` 是纯函数，输入输出确定，不依赖 MC 实例：

| 测试项 | 测试内容 | 优先级 |
|--------|---------|--------|
| 各类型组合 | scale 连乘、tint 逐通道连乘、attach_layer 全保留 | 高 |
| 优先级裁决 | base last-wins；同优先级按 install 序后装赢 | 高 |
| 发射降级 | 全部缺失 → DEFAULT；找不到 gun → DEFAULT；找不到 plugin → skip 该 | 高 |
| 非法值处理 | NaN/≤0 scale skip+WARN；tint clamp；unknown type skip+WARN | 中 |
| op 求值器单测 | 各 op（`>=` / `<=` / `==` / `>` / `<`）× 数值型/布尔型/STRING；UUID 拒绝；类型不匹配降级 | 高 |
| 状态条件触发 | `>=`/`==` 边界；state 缺失走默认值；domain 解析（per-bullet 命中 / 未命中回落 per-gun） | 中 |
| Codec round-trip | `BulletStyle` 新结构 encode→decode；`Modifier` dispatch 各类型 | 高 |
| Trait Codec round-trip | `Trait.visualModifiers` 渐进式加字段，缺省字段回退 empty list | 中 |

不测渲染层（`BulletRenderObject`/`BillboardRenderer` 依赖 MC client），归手动/集成测试，沿用现有设计文档"测试策略"的单元/集成划分。

## 7. 迁移与兼容

### 7.1 被取代的概念

- **旧 `BulletStyle` 整体覆盖语义**——退化为 base 覆盖（插件可设自己的 base，但仍会被另插件 base 按优先级覆盖；该插件的 modifiers 仍照样叠加，不再"整包替换"）。
- **`VisualStyleResolver`（`bullet/VisualStyleResolver.java`）**——废弃删除，由 `VisualCompositionService` 取代。
- **`BulletSyncService.resolveVisualStyle` 的内联枪械单查逻辑**——改为委托给 `VisualCompositionService`。

### 7.2 不变的部分

- `bullet_size` 属性管线、`CollisionDetector`、`BulletManager` 逻辑子弹——不变
- `DeltaBulletEntry`（仅位置方向）——不变
- `BulletS2CPacket` 的三桶结构（new/updated/removed + forceFullSync）——不变
- `onVisualTick` 钩子机制、`VisualTickHookDispatcher`、`ClientBulletSnapshot` ——不变（仍提供客户端动态兜底）
- `trait` 钩子类型、注册机制——不变；但 `Trait` record 定义与 Codec 改造（新增 `visualModifiers` 字段），见 §4.1
- `BulletSnapshot.stats/traits/state/damageType` 的可变性契约不变（javadoc 已标"故意可变、钩子可在飞行中改"），但**视觉层不再随这些字段飞行中变更而重组合**——组合结果创建瞬间冻结并缓存在 `BulletRecord`（详见 §2.1 "创建瞬间冻结"注）。钩子要影响视觉应走 `onVisualTick` 改 `BulletRenderObject`，不应改 `BulletSnapshot` 以期重组合。

### 7.3 协议变更

`FullBulletEntry` 是内部协议，纯增量字段，服务端/客户端 codec 同步改。无第三方依赖，无跨版本兼容负担。`bulletSize → renderScale` 是同位同类型改名（一个 float），codec 读仍是一个 float，wire 兼容性维持。

## 8. 范围之外（YAGNI）

以下明确不做，留给 `onVisualTick` 代码钩子或后续里程碑：

- 自旋（spin）/ 闪烁（pulse）等需要时间的视觉修饰符——交给 `onVisualTick` 钩子，声明式只管静态外观
- 子弹飞行中 state 变化自动重发——交 `onVisualTick` 钩子主动响应（路径①约束）
- 独立的子弹修饰符注册表（`modularshoot:bullet_visual_modifiers`）——B 方案明确不做，修饰符内联声明
- 每修饰符显式声明合并操作符（ADD/MULTIPLY/OVERRIDE）——自动规则已足，不增加使用者心智负担
